The application is a large Firebase + Node.js + TypeScript system for managing:

Booking

Consultations

Internal Calendar

Google Calendar sync

Timezone handling (Europe/Rome vs UTC)

Currently, each module implements its own logic for:

generating available time slots

handling weekdays

parsing hours and minutes

validating excluded days

checking conflicts

converting dates to UTC

syncing with Google Calendar

These implementations were created at different moments, in different files, with different rules, causing severe inconsistencies.

❗ Actual symptoms:

Wrong available slots shown to clients

Misaligned timezones (UTC vs Europe/Rome)

Conflicts (409) triggered incorrectly

Google Calendar events ignored or incorrectly mapped

Slots shown available when they should be blocked

Different front-end modules produce different results

Duplicate and conflicting backend logic producing drift

The system is unstable because BOOKING, CONSULTATIONS, and NATIVE CALENDAR all calculate slots in different ways.

We need to fully centralize the logic.
