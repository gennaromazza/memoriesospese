Refactor Sicuro & Performante del Sistema Gallerie (senza cambiare la UI)

CONTESTO
Sto sviluppando un sistema di gallerie fotografiche avanzato (clienti wedding) basato su React + TypeScript + Firebase (Firestore + Storage).
Il sistema oggi funziona, ma la logica delle foto è distribuita in troppi punti e questo crea lentezza e difficoltà di manutenzione.

La UI delle gallerie pubbliche NON deve essere modificata.
Il comportamento lato cliente non deve cambiare in nessun modo.

L’obiettivo del lavoro è solo interno:

ottimizzare

unificare

ripulire

velocizzare
senza rompere niente.

✅ COSA DEVE FARE IL REFACTOR
1. Creare un unico hook centrale: useGalleryPhotos()

Questo hook deve:

usare come unica fonte primaria la collezione photos filtrata per galleryId

gestire l’ordinamento

gestire admin/guest/legacy

gestire la paginazione vera (startAfter)

gestire i fallback:

legacy galleries/{galleryId}/photos

Storage (1 sola volta)

gestire deduplicazione filename

esporre:

{
  photos,
  guestPhotos,
  legacyPhotos,
  loadMorePhotos,
  isLoading,
  hasMore,
  progress
}


⚠️ Importantissimo:

I fallback DEVONO RIMANERE, non vanno eliminati.
Se mancano foto in Firestore, si usa comunque la logica attuale.

2. Spostare tutto il codice di caricamento foto dentro useGalleryPhotos()

Questo significa:

nessun caricamento foto duplicato in useGalleryData

nessun caricamento foto duplicato in EditGalleryModal

nessun listAll() ripetuto

nessuna query repetuta

nessun controllo duplicati fatto in 3 punti diversi

3. Ripulire useGalleryData e farlo dipendere da useGalleryPhotos

Dopo il refactor, useGalleryData deve:

caricare solo la galleria (dettagli)

caricare solo gli extra (youtube, specialTheme, password, pin)

generare l’oggetto gallery

importare da useGalleryPhotos() tutta la parte foto

Esempio:

const {
  photos,
  guestPhotos,
  legacyPhotos,
  loadMorePhotos,
  ...
} = useGalleryPhotos(galleryId, galleryData);

4. Ottimizzare il fallback Storage (importantissimo)

Oggi il fallback Storage è fatto più volte.

Requisiti:

Deve essere fatto 1 sola volta per galleria (usa memo/cache interna)

Deve essere centralizzato nel nuovo hook

Non deve MAI cancellare nulla

Non deve mai cambiare path

Non deve spostare file

Deve solo leggere

Quando trova foto mancanti, può inserirle in Firestore (photos)

5. Sistemare la paginazione vera

Requisiti:

utilizzare startAfter(lastDoc)

evitare loop di duplicati

caricare solo nuovi batch

non ricaricare sempre tutto

6. Rendere la pagina pubblica Gallery più leggera (ma identica)

Requisiti:

la UI deve rimanere la stessa

ma tutta la logica di caricamento foto deve sparire da lì

la pagina deve solo:

mostrare foto

mostrare loading

mostrare progress

eseguire loadMorePhotos sullo scroll
