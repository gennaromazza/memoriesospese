2. Patch raccomandate nel QuoteTemplatesManager
2.1. AlertDialog – evita comportamenti strani

In fondo hai:

<AlertDialog
  open={!!deleteTemplateId}
  onOpenChange={() => setDeleteTemplateId(null)}
>


Cambialo così:

<AlertDialog
  open={!!deleteTemplateId}
  onOpenChange={(open) => {
    if (!open) {
      setDeleteTemplateId(null);
    }
  }}
>


Così non richiami setDeleteTemplateId(null) anche quando Radix prova ad aprire il dialog.
Non è quasi mai causa di “maximum depth”, ma è un pattern da evitare.

2.2. Switch nella card – usa direttamente il valore checked

Adesso:

const handleToggle = useCallback(() => {
  if (isToggling) return;
  setIsToggling(true);
  onToggle();
  setTimeout(() => setIsToggling(false), 1000);
}, [onToggle, isToggling]);

<Switch
  checked={template.attivo}
  onCheckedChange={handleToggle}
  disabled={isToggling}
  data-testid={`switch-template-${template.id}`}
/>


Qui sfrutti lo switch solo come “click”, ignorando il valore checked.
Io lo semplificherei così:

const handleToggle = useCallback(
  (checked: boolean) => {
    if (isToggling) return;
    setIsToggling(true);
    onToggle(); // qui dentro fai già il !template.attivo
    setTimeout(() => setIsToggling(false), 300);
  },
  [onToggle, isToggling]
);

// ...

<Switch
  checked={template.attivo}
  onCheckedChange={handleToggle}
  disabled={isToggling}
  data-testid={`switch-template-${template.id}`}
/>


Oppure ancora più diretto, eliminando isToggling e lasciando solo la mutation:

<Switch
  checked={template.attivo}
  onCheckedChange={(checked) =>
    toggleMutation.mutate({
      id: template.id,
      attivo: checked,
    })
  }
  data-testid={`switch-template-${template.id}`}
/>


e togli completamente isToggling e handleToggle dal componente.

Questo ti assicura che:

ogni click → una sola mutate

nessun setState strano agganciato a callback che può essere richiamata più volte da Radix.
