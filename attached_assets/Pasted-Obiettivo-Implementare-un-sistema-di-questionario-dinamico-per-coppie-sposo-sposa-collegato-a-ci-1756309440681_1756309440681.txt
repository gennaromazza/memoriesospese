Obiettivo

Implementare un sistema di questionario dinamico per coppie (sposo/sposa), collegato a ciascuna galleria, con:

gestione domande da admin (Faq.tsx);

invio di due link univoci (sposo/sposa) al questionario;

salvataggio risposte separato (bride/groom), con ripresa progressi;

pulsante “Esporta risposte” che genera un testo “prompt-ready” da incollare in ChatGPT;

nessun uso di API LLM (niente chiavi lato client);

privacy garantita (risposte non visibili agli ospiti).

1) Struttura Firestore (Collections/Docs)

galleries/{galleryId}

couple: { brideName, groomName, weddingDate, emailBride, emailGroom }

questionnaire: {
enabled: boolean,
faqVersion: string, // per tracciare il set domande
links: {
bride: { token: string, url: string, createdAt: TS, usedAt: TS|null },
groom: { token: string, url: string, createdAt: TS, usedAt: TS|null }
}
}

answers: {
bride: {
status: "draft"|"submitted",
updatedAt: TS,
q: { q1: string, q2: string, ... q10: string }
},
groom: {
status: "draft"|"submitted",
updatedAt: TS,
q: { q1: string, q2: string, ... q10: string }
}
}

faqSets/{faqId}

title: string

active: boolean

questions: Array<{ id: "q1".."q10", label: string, type: "text"|"textarea" }>

createdAt: TS, updatedAt: TS

Nota: usare q1..q10 come chiavi stabili per mappare facilmente domande/risposte.

2) Routing / URL

Admin:

/admin/galleries/:galleryId/questionnaire → QuestionnaireManager

/admin/faq → Faq (gestione domande)

Pubblico (privato per la coppia, via token):

/q/:galleryId?token=XXXX&role=bride

/q/:galleryId?token=YYYY&role=groom

3) Componenti da creare
3.1 Faq.tsx (Admin)

Funzioni:

CRUD set domande (crea/edita/elimina).

Attiva un set come “corrente” (active = true → disattivare gli altri).

Campi per ogni domanda:

id (q1..q10, fisso), label, type (textarea di default).

Salvataggio in faqSets.

Esporta in localStorage il faqId attivo per memorizzare la scelta admin (opzionale).

3.2 QuestionnaireManager.tsx (Admin)

Funzioni:

Attiva/Disattiva questionario (questionnaire.enabled).

Associa faqVersion (legge il set attivo da faqSets).

Genera due link (uno sposa, uno sposo) creando token sicuri (es. 32+ chars, crypto-random).

Mostra/stampa i link.

Stato compilazione (draft/submitted) per bride/groom + last update.

Pulsante “Esporta risposte (prompt ChatGPT)” che apre modal con testo generato (vedi §5).

Scrive in galleries/{galleryId}/questionnaire.links.{bride|groom} i token/URL.

3.3 QuestionnaireForm.tsx (Public)

Legge galleryId, token, role dai parametri URL.

Valida token confrontandolo con galleries/{galleryId}/questionnaire.links[role].token.

Carica il set domande attivo via faqVersion.

Form a step (1 domanda per step, Avanti/Indietro, salvataggi auto in draft).

Autosave ogni 2-3 sec o onBlur (scrive in answers[role].q.qX).

CTA finale “Invia” → answers[role].status = "submitted".

Ripresa progressi (se status = draft, riparte dall’ultimo qX compilato).

Controlli:

Rate limit minimale (es. blocco submit multipli entro 10s).

Consenso privacy (checkbox).

Messaggio: “Le vostre risposte sono visibili solo a voi e al fotografo.”

3.4 ResponseExportButton.tsx (Admin)

Props: { galleryId: string }

Legge:

dati coppia (nomi, data),

domande (label da faqVersion),

risposte bride/groom.

Genera testo prompt-ready (vedi §5) con:

intestazione,

risposte tabellate,

istruzioni per la generazione dei testi per album,

formatting robusto per incolla su ChatGPT.

Mostra modal con textarea read-only + pulsante “Copia”.

4) Sicurezza / Firestore Rules (indicazioni)

Solo admin può leggere/scrivere faqSets e tutti i campi sotto galleries/* eccetto accessi pubblici limitati.

Accesso pubblico a /q/:galleryId:

Consentire solo:

lettura galleries/{galleryId}.questionnaire.links[role] limitata alla validazione del token (idealmente via Cloud Function/Callable; in assenza, minimizzare dati esposti);

lettura set domande attivo (solo labels, nessun dato sensibile);

lettura/scrittura answers[role] solo se token valido e solo per quel role.

Gli ospiti (non autenticati e senza token) non devono poter leggere answers né questionnaire.

Suggerito: usare Cloud Functions per validare token e firmare una sessione temporanea; se non disponibile, ridurre al minimo i dati leggibili pubblicamente.

5) Contenuto generato dal pulsante “Esporta risposte (prompt ChatGPT)”

Il componente ResponseExportButton deve generare esattamente il testo seguente, sostituendo i segnaposto tra {{ }} con i valori reali e concatenando le 10 domande (label) e le risposte di sposa e sposo.

Template da generare (testo semplice, pronto per incolla)
RUOLO
Sei un senior wedding storyteller. Devi trasformare risposte di questionario in testi brevi e poetici da impaginare in un album di matrimonio fisico + digitale (Memorie Sospese).

OBIETTIVO
Genera:
1) 6–9 micro-testi (max 180–220 caratteri ciascuno) da inserire tra le pagine (preparativi, cerimonia, amici, primo ballo, promessa, futuro).
2) 1 testo di apertura (max 300 caratteri) e 1 di chiusura (max 300 caratteri).
3) 3 didascalie “emozionali” (max 120 caratteri) per pagine foto full-bleed.
4) 1 sezione “Promessa sigillata” (solo per gli sposi, tono intimo, max 250 caratteri).

TONO & STILE
- Intimo, elegante, concreto; niente cliché vuoti.
- Scrivi in italiano naturale, frasi brevi, immagini evocative.
- Usa le loro parole quando possibile (parafrasa se serve).
- Evita nomi di terzi non citati nelle risposte.

CONTESTO COPPIA
- Sposi: {{couple.brideName}} & {{couple.groomName}}
- Data matrimonio: {{couple.weddingDate}}

DOMANDE & RISPOSTE
{{#for each question q1..q10}}
- {{label(qX)}}
  • Risposta SPOSA: {{answers.bride.q.qX || "—"}}
  • Risposta SPOSO: {{answers.groom.q.qX || "—"}}
{{/for}}

VINCOLI
- Non superare i limiti di caratteri indicati.
- Non inventare fatti non presenti.
- Se una risposta manca, ignora la domanda e non forzare contenuti.

OUTPUT RICHIESTO (JSON)
Restituisci ESCLUSIVAMENTE questo JSON valido:
{
  "apertura": "string, <=300 char",
  "microtesti": ["string<=220", "string<=220", "string<=220", "string<=220", "string<=220", "string<=220"],
  "didascalie": ["string<=120", "string<=120", "string<=120"],
  "promessa_sigillata": "string<=250",
  "chiusura": "string<=300",
  "note_impaginazione": [
    "Suggerisci in 3-5 righe come distribuire i microtesti tra le sezioni dell'album, es. Pag. preparativi: microtesto #1; cerimonia: #2; amici: #3; primo ballo: #4; promessa: #5; futuro: #6."
  ]
}


Nota: il testo generato deve essere semplice testo, nessun markdown nel JSON. Il componente mostrerà questo blocco in una modal con “Copia”.

6) UX dettagli

QuestionnaireForm:

Stepper con 10 domande (q1..q10).

Progress bar; indicazione “salvataggio…” durante autosave.

Alla fine: checkbox privacy + bottone “Invia” → submitted.

Conferma: “Grazie! Potrete rivedere/modificare finché l’album non verrà impaginato.”

QuestionnaireManager:

Toggle enable/disable questionario.

Select “Set domande attivo” (legge faqSets.active=true).

Bottoni “Genera link sposa” / “Genera link sposo”.

Stato: bozza/inviato, last update per ciascuno.

Esporta risposte (prompt ChatGPT) → apre modal con template compilato + “Copia”.

7) Dettagli tecnici consigliati

Token: crypto.getRandomValues (browser) o Node crypto; 32–48 bytes hex/base64url.

Validazione token: scadenza opzionale (es. 90 giorni).

Rate-limit submit: blocca doppio invio entro 10s.

Textarea con auto-grow; salvataggio trim(); limite 1200–1500 caratteri per risposta lunga.

i18n: etichette statiche italiane, future-proof per lingua.

Accessibilità: focus management tra step, aria-labels.

8) Domande (label) predefinite da caricare nel set attivo

Usare come set iniziale (faqVersion es. “v1”):

q1: Il Momento della Scintilla

q2: Una Difficoltà Superata Insieme

q3: Il Momento più Divertente o Folle

q4: La Vostra Canzone del Cuore

q5: La Promessa per il Futuro

q6: Il Vostro Piccolo Rituale di Coppia

q7: Il Colore o Tema del Matrimonio

q8: Un Aggettivo per il Vostro Giorno Perfetto

q9: Le Persone Importanti (famiglia/cerchia, ruoli speciali)

q10: Spazio Libero (qualsiasi cosa vogliate aggiungere)

Tutte type: "textarea".
