2. sendNewPhotosNotificationCall (quella che ti sta dando problemi)
export const sendNewPhotosNotificationCall = functions.https.onCall(async (data, context) => {
  try {
    const { galleryName, newPhotosCount, uploaderName, galleryUrl, recipients } = data;

    if (!recipients || recipients.length === 0) {
      throw new functions.https.HttpsError('invalid-argument', 'Recipients list is required');
    }

    const { sendGmailEmail, createNewPhotosEmailHTML } = await import('./gmail');
    
    const htmlContent = createNewPhotosEmailHTML(galleryName, uploaderName, newPhotosCount, galleryUrl);
    const subject = `${newPhotosCount} nuova${newPhotosCount > 1 ? 'e' : ''} foto in "${galleryName}"`;

    await sendGmailEmail(recipients, subject, htmlContent);

    return { success: true, message: 'Notification sent successfully' };
  } catch (error) {
    functions.logger.error('Error sending new photos notification:', error);
    throw new functions.https.HttpsError('internal', 'Failed to send notification email');
  }
});


Questa invece NON ha:

.runWith({ secrets: ['REPL_IDENTITY'] })


Quindi quando prova a fare await import('./gmail') e poi sendGmailEmail(...), quella sendGmailEmail cerca di leggere le credenziali Gmail… ma qui la funzione non ha accesso ai secrets, quindi va in errore interno → e tu dal frontend vedi functions/internal / 500 / "Failed to send notification email".

💡 Questo spiega perfettamente perché:

la funzione password (che usa lo stesso motore email) funziona ✔

la notifica nuove foto no ✖

Non è CORS, non è Auth, non è Firestore.
È semplicemente: sendNewPhotosNotificationCall non sta dichiarando i secrets.

La fix

Dobbiamo dare a sendNewPhotosNotificationCall lo stesso environment “privilegiato” dell’altra.

Quindi la riscriviamo così:

export const sendNewPhotosNotificationCall = functions
  .runWith({ secrets: ['REPL_IDENTITY'] }) // ⬅︎ aggiunto
  .https.onCall(async (data, context) => {
    try {
      const {
        galleryName,
        newPhotosCount,
        uploaderName,
        galleryUrl,
        recipients
      } = data;

      // 1. Validazioni argomenti
      if (!recipients || !Array.isArray(recipients) || recipients.length === 0) {
        throw new functions.https.HttpsError(
          'invalid-argument',
          'Recipients list is required'
        );
      }
      if (!galleryName || !galleryUrl) {
        throw new functions.https.HttpsError(
          'invalid-argument',
          'Missing gallery data'
        );
      }

      // 2. (Opzionale ma consigliato) Controllo autenticazione
      // Se vuoi limitarla solo a utenti loggati/admin:
      // if (!context.auth) {
      //   throw new functions.https.HttpsError(
      //     'unauthenticated',
      //     'User must be authenticated'
      //   );
      // }

      // 3. Lazy import del modulo Gmail (usa le credenziali segrete)
      const { sendGmailEmail, createNewPhotosEmailHTML } = await import('./gmail');

      // 4. Costruzione email
      const htmlContent = createNewPhotosEmailHTML(
        galleryName,
        uploaderName,
        newPhotosCount,
        galleryUrl
      );

      const subject = `${newPhotosCount} nuova${
        newPhotosCount > 1 ? 'e' : ''
      } foto in "${galleryName}"`;

      // 5. Invio email
      await sendGmailEmail(recipients, subject, htmlContent);

      functions.logger.info(
        `✉️ Notifica nuove foto inviata a ${recipients.length} destinatari per ${galleryName}`
      );

      // 6. Risposta al client
      return { success: true, message: 'Notification sent successfully' };
    } catch (error) {
      functions.logger.error('❌ Error in sendNewPhotosNotificationCall:', error);

      // Ritorniamo errore "pulito" al client
      throw new functions.https.HttpsError(
        'internal',
        error instanceof Error ? error.message : 'Failed to send notification email'
      );
    }
  });


Cosa abbiamo fatto di importante:

runWith({ secrets: ['REPL_IDENTITY'] }) → adesso la callable può leggere lo stesso secret Gmail dell’altra funzione che già funziona.

Log più espliciti (functions.logger.info, functions.logger.error) così nei log console vedi quante email ha provato a mandare e, se crasha, il motivo vero.

Controllo degli argomenti in ingresso (così se la chiami vuota dal frontend ti dice invalid-argument invece di 500 generico).

Cosa devi controllare dopo aver aggiornato

Ridistribuire solo questa funzione (risparmi tempo):

firebase deploy --only functions:sendNewPhotosNotificationCall


Dal frontend, la stai già chiamando bene:

const _sendNewPhotosNotificationCallable = httpsCallable(
  functions,
  "sendNewPhotosNotificationCall"
);

await _sendNewPhotosNotificationCallable({
  galleryName,
  newPhotosCount,
  uploaderName,
  galleryUrl,
  recipients: subscribers,
});


Questo è giusto. Non serve fetch. Non serve CORS. Non serve Bearer token. Perfetto così 🔥

Ricapitoliamo in modo secco

Il problema NON è più CORS.

Il problema NON è Firestore.

Il problema NON è l'autenticazione lato client.

Il problema è che sendNewPhotosNotificationCall sta cercando di usare sendGmailEmail SENZA dichiarare i secrets necessari → quindi crasha.

Aggiungendo .runWith({ secrets: ['REPL_IDENTITY'] }) sulla callable sendNewPhotosNotificationCall, la rendi simmetrica alla sendGalleryPasswordV2 (che funziona già) e risolvi quel 500/403 interno.

Fai questa modifica server-side, redeployi la funzione, e poi le notifiche nuove foto dovrebbero partire come le email password. 💪
