Con la password inserita a mano entri → quindi la galleria esiste e i dati in Firestore sono ok.

Cliccando “Richiedi password” parte il flusso che chiama la Cloud Function getGalleryMetadata (si vede nella console) e torna:

Errore getGalleryInfo: { code: 'functions/internal', name: 'FirebaseError' }


→ significa che la funzione sta lanciando un errore non “tipizzato” (o è scritto come onRequest ma la chiami come onCall). In entrambi i casi, il client riceve un generico functions/internal e tu mostri “Galleria non trovata”.

Fix immediato (server + client)
1) Assicurati che la funzione sia davvero onCall e che ritorni un payload, non usi res

Server — functions/src/getGalleryMetadata.ts

- import * as functions from 'firebase-functions'
+ import * as functions from 'firebase-functions'
+ import * as admin from 'firebase-admin'

+ // opzionale: log migliore su Gen1
+ const log = functions.logger

- export const getGalleryMetadata = functions.https.onRequest(async (req, res) => {
-   const { code } = req.body || {}
-   ...
-   if (!doc.exists) throw new Error('Gallery not found')
-   res.json({ galleryId: doc.id, ...doc.data() })
- })
+ export const getGalleryMetadata = functions.https.onCall(async (data, context) => {
+   try {
+     const code = (data?.code || '').trim().toUpperCase()
+     if (!code) {
+       throw new functions.https.HttpsError('invalid-argument', 'Missing code')
+     }
+     // admin SDK bypassa le rules
+     const snap = await admin.firestore()
+       .collection('galleries')
+       .where('accessCode', '==', code)
+       .limit(1)
+       .get()
+
+     if (snap.empty) {
+       throw new functions.https.HttpsError('not-found', 'Gallery not found', { code })
+     }
+     const doc = snap.docs[0]
+     const dataOut = { galleryId: doc.id, ...doc.data() }
+     log.info('getGalleryMetadata OK', { code, galleryId: doc.id })
+     return dataOut
+   } catch (err: any) {
+     // Se arriva un errore “normale”, wrappalo in HttpsError per il client
+     if (err instanceof functions.https.HttpsError) throw err
+     log.error('getGalleryMetadata FAIL', { err: err?.message })
+     throw new functions.https.HttpsError('internal', 'Unexpected error')
+   }
+ })


Se la tua funzione era già onCall, il punto cruciale è: mai throw new Error(...) e mai usare res/req dentro un onCall. Usa sempre HttpsError e return un oggetto.

2) Lato client: chiama onCall nel regione giusta e passa code

Client — dove richiami la funzione

- import { getFunctions, httpsCallable } from 'firebase/functions'
- const functions = getFunctions() // default
- const getMeta = httpsCallable(functions, 'getGalleryMetadata')
- const resp = await getMeta({ code })
+ import { getFunctions, httpsCallable } from 'firebase/functions'
+ const fn = httpsCallable(getFunctions(firebaseApp, 'us-central1'), 'getGalleryMetadata')
+ const { data } = await fn({ code })
+ // usa data (es. data.galleryId, data.title, ...)

3) (Se usi App Check) non bloccare la richiesta di test

Se hai abilitato App Check enforcement, per provare subito:

// server
export const getGalleryMetadata = functions
  .runWith({ /* mem/timeout qui */ })
  .https.onCall({ /* v4 supporta option */ /* @ts-ignore */ allowInvalidAppCheckToken: true }, handler)


Oppure disabilita temporaneamente l’enforcement su questa funzione da console.

4) Log utili

Aggiungi log lato server (già nel diff) per vedere code ricevuto e ID trovato.
Se dai per scontato case-insensitive sul codice, normalizzalo (toUpperCase() anche lato client).

Perché ora funziona

Prima il server lanciava Error o mixava onRequest/onCall, e il client riceveva lo status generico functions/internal → tu mostri “Galleria non trovata”.

Ora la funzione risponde sempre in modo tipizzato (HttpsError) o ritorna un oggetto con i metadati → il client può distinguere not-found (codice sbagliato) da veri errori tecnici.
