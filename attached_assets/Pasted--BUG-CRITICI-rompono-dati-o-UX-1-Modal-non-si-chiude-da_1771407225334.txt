❌ BUG CRITICI (rompono dati o UX)
1) Modal non si chiude davvero: bottone “Annulla” bypassa la confirm

Hai:

<Dialog open={open} onOpenChange={handleDialogChange}>

<Button type="button" onClick={onClose}>Annulla</Button>

Problema

handleDialogChange fa la confirm “modifiche non salvate”

ma il bottone chiama onClose diretto → chiude senza conferma

✅ Fix: usa handleDialogChange(false) oppure estrai una requestClose().

const requestClose = () => handleDialogChange(false);

// ...
<Button type="button" onClick={requestClose}>Annulla</Button>

2) In edit mode non resetti lo stato UI (template / expanded / immagini)

Quando carichi existingQuote, aggiorni form, ma NON resetti:

selectedTemplateId

expandedProducts

uploadingImages

Risultato:

apri un quote A → poi quote B → ti ritrovi UI “sporca” (prodotti espansi sbagliati, template selezionato vecchio)

✅ Fix (in effect di load existingQuote):

setSelectedTemplateId(existingQuote.templateId ?? '');
setExpandedProducts(new Set()); // o espandi i primi
setUploadingImages({});

3) Query key job incoerente (cache mismatch)

Qui:

queryKey: ['jobs', jobId]


Altrove nel tuo codice spesso usi ['job', jobId] o ['jobs', jobId] (hai già mostrato pattern misti).

Problema: invalidate/refetch potrebbero non colpire il job giusto → preview pagamenti/eventDate stale.

✅ Fix: standardizza. Se usi ['job', jobId] altrove, usa quello anche qui.

4) Pagamento preview usa job.eventDate invece della data del form

Preview:

const eventDate = job?.eventDate ? ... : null;
return calculatePaymentSchedule(totalAfterDiscount, paymentConfig, eventDate || undefined);


Ma nel builder potresti voler usare una eventDate modificabile / diversa dal job (o job non ancora aggiornato).

Bug pratico:

job.eventDate è null o vecchio → preview scadenze sbagliate

ma l’admin pensa che sia corretto

✅ Fix: se vuoi “reference evento”, usa job.eventDate ok, ma allora:

mostra warning “evento senza data”

o disable useEventDateReference se job.eventDate mancante

5) onInteractOutside preventDefault blocca chiusura naturale + focus trap edge-case
onInteractOutside={(e) => e.preventDefault()}


Questo:

impedisce click outside per chiudere (ok se voluto)

ma può rompere interazioni con portali (Select/Popover) in alcuni casi

e può rendere il dialog “intrappolato” se l’utente vuole solo chiudere

Se già hai confirm, meglio lasciare Radix fare il suo e gestire onOpenChange.

✅ Fix: rimuovilo o applicalo solo quando createMutation.isPending.

9) Aggiorni selectable su tutti i prodotti a cambio type, MA…

⚠️ BUG UI/UX
10) Prodotti frequenti: Select con value="" fisso
<Select value="" onValueChange=...>


Radix non ama value controllato sempre uguale:

può impedire selezioni ripetute della stessa voce

può dare warning controllato/ non controllato

✅ Fix: usa stato frequentSelected, e poi reset a '' dopo append.

const [freq, setFreq] = useState('');
<Select value={freq} onValueChange={(v)=>{ setFreq(v); ...; setFreq(''); }}>
